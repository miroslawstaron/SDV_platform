# Reference components and data

Source adaptation attribution is included in `native/adapter.cpp`. SIL Kit patterns come from Vector Informatik GmbH's MIT-licensed lifecycle/CAN examples. SOME/IP patterns come from BMW/COVESA's MPL-2.0 examples. The vSomeIP compatibility change is provided as `native/patch-vsomeip.py`; the complete modified source and upstream license are included in built images. Upstream repositories and exact versions are listed in `backend/dependencies.json` and `dependencies.lock.json`.

`contracts/vss.json` is the unmodified COVESA VSS v6.1 release artifact, licensed under MPL-2.0. The default Gothenburg OSM extract was downloaded on 2026-10-12 from `https://api.openstreetmap.org/api/0.6/map?bbox=11.958,57.700,11.979,57.711`, then filtered to highway ways and their referenced nodes. Source data is retained in `backend/fixtures/gothenburg.osm.xml`. The legacy Stockholm extract from Overpass Kumi remains in `backend/fixtures/stockholm.osm.xml` for provenance of earlier recordings; new drives default to Gothenburg. Both extracts contain data © OpenStreetMap contributors, licensed under ODbL 1.0; generated road networks preserve attribution. See [OpenStreetMap copyright and license](https://www.openstreetmap.org/copyright).

MapillaryJS 4.1.2 is an MIT-licensed viewer from Meta Platforms, Inc. and affiliates, pinned in `web/package.json` and `web/package-lock.json`. Its full upstream license is retained in `web/public/licenses/mapillary-js.txt` and served at `/licenses/mapillary-js.txt`. The integration follows the upstream [viewer setup](https://mapillary.github.io/mapillary-js/docs/intro/try/) and [Graph API demo](https://github.com/mapillary/api-demo) patterns, using bounded image searches and the official viewer; no upstream demo access token is bundled or reused. Imagery is supplied by Mapillary and its contributors under the provider's applicable terms. The viewer's provider, contributor and capture-date attribution remains enabled. The SDK data provider preloads image bytes in bounded browser memory, with three decoded viewer buffers for 25 m image steps. Closing the driver window clears these caches. Images actually displayed during live driving are archived with provider image IDs and capture metadata in a separate persistent similarity database; they are excluded from the vehicle recording database and exports. Users supply their own application client token, which is never archived.

Pillow **11.3.0** is pinned in `backend/requirements.txt` and distributed under its MIT-CMU license. Upstream source and license: [python-pillow/Pillow](https://github.com/python-pillow/Pillow/tree/11.3.0). It decodes captured image bytes, handles EXIF orientation, converts to grayscale and resizes before the platform's own 64-bit DCT pHash calculation.

## Presentation and instrument display

reveal.js **6.0.2** is MIT licensed. The pinned runtime and notes plugin, copied from the user's existing Metriczone 5G project's vendored distribution, are served locally under `web/public/presentation/vendor`; the original license and source/version notice are included there. Upstream: https://github.com/hakimel/reveal.js/releases/tag/6.0.2. The slide content is specific to this platform.

The independent instrument display uses the same digest-pinned nginx 1.27 Alpine base as the web image (BSD-2-Clause nginx license); application sources are local. The user's original Metriczone logo is copied unchanged, with its proportions preserved, into the engineering, driver, instruments and presentation views. Imagery preload/display stations are 25 metres apart; Mapillary matching still uses the existing 50-metre selection radius.
